# 工作区 VM 存储迁移至 VFS

[English](guide.md) | 中文

## 变更

两种工作区 VM 模式使用相同的 VFS 目录和 UID/GID 绑定。多会话 VM 跨回合保留实例；关闭、空闲回收、归档或删除会释放实例，不创建磁盘快照。工作区文件留在 VFS 中。工作区挂载之外安装的工具和配置不会在 VM 重建后保留。工作区文件仍被保留时，预留身份继续占用，即使没有运行中的 VM。

现有基于快照的多会话 VM 部署需要显式迁移数据。旧云记录并非 VFS 分配记录；保留快照不会使其中的文件自动通过 VFS 提供方可用。Session 日志代次保持不变。

## 迁移

1. 备份工作区登记、私有云记录、SSH 密钥、VFS 身份状态和源文件。导入经验证并持久记录之前，保留所有原快照。旧分配状态和 VFS 分配状态使用独立的私有目录。
2. 迁移运行中的 VM 前，阻止新消息、上传和命令。停止并等待客体机写入收束，导出源工作区，验证文件，再通过原提供方关闭 VM，然后变更存储。不得将空 VFS 目录挂载到唯一活跃副本之上。
3. 将 `vultr.legacyMultiStateRoot` 设为原私有云状态目录。自动导入只接受已确认关闭的记录及其已发布完整文件副本；运行中或不完整的记录需要通过旧提供方恢复。按正确 UID/GID 导入已分配的 VFS 目录，并确认持久发布。导入不修改原记录，也不删除快照。文件冲突、不完整副本、结果未知的云修改或未确认的清理会保留原状态和源数据。
4. 为 `vultr.multi` 和 `vultr.single` 配置相同 `volumeId` 和 `region`，分配状态使用独立的私有 `stateRoot` 目录。按 [Vultr 部署指南](../../../user/guide/workspace-vultr.zh.md#offer-vm-and-docker-modes-together)配置共享身份池，保留现有绑定，并将 `workspace.defaultMode` 保持为 Docker。身份池计入保留的目录，而不只计入活跃实例。通过部署镜像或重建后可重复执行的安装提供必要工具。
5. 验证 VM 关闭时上传和下载可用、执行访问相同 VFS 文件，以及关闭和重开不创建新快照。确认关闭后原 VFS 连接和 VM 已消失。只有验证导入并持久发布后才回收旧快照，随后解除维护限制。
