# 工作区归档与资源回收

[English](guide.md) | 中文

## 变更

删除工作区会停止其会话活动并等待沙箱回收。VM 保存和销毁可能耗时较长；回收失败时保留登记。访客可以删除自己的登记。文件与会话日志继续保存在磁盘上。

工作区归档保存在区域版本 4。当前读取器接受版本 3 记录，缺少归档信息表示活动状态。旧程序无法打开版本 4 工作区数据；回滚需要使用升级前匹配的工作区存储备份。

## 迁移

1. 升级前停止应用并备份工作区存储。单独保留会话日志、文件与云端状态。
2. 同时升级服务端和客户端。自定义工作区客户端需实现 `setArchived(workspaceId, archived)`，并接受记录中可选的 `archived` 字段。自定义模式提供者需实现 `SandboxExecutionBackend.closeWorkspace`，且不得再次获取模式租约，因为登记服务已经持有独占锁。通过 `registerDeletionGuard` 登记的回调也会在归档时执行，必须保留文件与会话日志。
3. 提高 Docker 容量时，在 Runner 配置中显式设置 `maxInstances`；允许值为 1–100，默认值仍为 2。
4. 确认归档释放资源并保留文件，恢复不会启动资源，回收失败时登记仍然可见。确认不会使用旧程序打开版本 4 工作区数据。
