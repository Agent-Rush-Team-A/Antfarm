# Agent Note: 工作区上传的排他发布

Status: implemented

[English](2026-11-05-workspace-upload-publication.md) | 中文

## 问题

工作区上传写入沙箱进程可见的目录。直接写入目标会暴露不完整字节，跟随目标符号链接可能修改另一个文件。响应可能在发布之后丢失。

## 决策

[上传服务](../../../../packages/api/workspace-upload/README.zh.md)将受大小限制的字节暂存到私有兄弟目录，再通过已打开的工作区描述符创建排他硬链接。它同步文件和发布目录，保留现有目录项，并在后续操作失败时仍报告是否已发布。部署负责可信父目录、共享文件系统和容器组。

[Peer 权限机制](2026-10-12-peer-principal-and-remote-access.zh.md)保留精确路由默认仅允许 owner 的行为。显式注册的元数据授权器可接纳资源作用域路由；修改处理器在发布前重新检查权限。工作区上传是首个消费者。[聊天附件上传](../feature/2026-08-26-generic-file-upload.zh.md)保留独立的存储与生命周期契约。

## 验证

存储测试检查字节保真、路径与符号链接限制、排他重名、取消和暂存清理。真实 Web 验收检查工作区归属权限、可见结果、登出和卸载。容器验收检查非 root Bash 进程读取上传字节，并通过工作区共享组写入。

## 考虑过的替代方案

直接写入目标会暴露部分内容，并在沙箱改变该目录项时增加取消清理的复杂度。重命名暂存文件会替换现有目录项。先检查文件名再写入会与另一个创建者竞态。通过描述符锚定的排他发布可以保留旧文件并避免这些窗口。

## 影响

服务依赖 Linux 描述符路径和同文件系统的可信兄弟暂存区域。每项上传持有其资源直到清理完成；卸载停止接纳并等待活动上传结束。丢失响应仍是未知结果，发布后失败会保留已提交文件。
